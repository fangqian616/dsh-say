# 语音汇报（voice-report）

让 AI 的汇报不只是文字 —— 同时从音响里念出来，而且用的是一条固定的人设声线。

## 什么时候用

**触发**：
- 用户说"念给我听""用语音回答""说出来"
- 你完成了一段实质性工作，要向用户汇报进展、结论、下一步
- 用户要改播报角色的性格、语气、声线、语速

**不要用**：
- 一句话的确认（"好的""已经删除了"）—— 念出来只是噪音
- 用户明确说"别出声""只要文字"
- 纯代码、表格、文件路径这类不适合朗读的内容（改为念摘要）
- 报错、失败信息（先说清楚问题，不要用角色声音念失败）

## 前置检查

播报依赖 `dsh-voice` 插件提供 `tts_speak` 工具。**先确认工具可用**：

```
tts_engines
```

- `selected: builtin` → 可以播报，用系统语音，零依赖
- `selected: gpt-sovits` → 可以播报，用角色声线
- 两个后端都不可用 → **不要播报**，只给文字，并说明原因

若 `tts_speak` 不在你的工具列表里，说明插件没挂载 —— 告知用户，不要假装念了。

## 操作步骤

### 1. 读人设

人设存放在 `soul/` 目录，每个角色一个 Markdown 文件：

```
soul/
├─ voice-pack.json        当前默认声线包名
├─ <角色名>.md            角色人设与播报风格
└─ _template.md           新建人设的模板
```

读 `soul/` 下的角色文件，取得：**语气、节奏、称呼方式、禁忌**。默认用 `voice-pack.json` 里指定的那一个；该字段留空时，用插件配置的默认声线，再没有就退回系统语音。

### 2. 生成播报稿

**这是最容易做错的一步。**

- 播报稿必须是**你真正回复给用户的文字**的精炼版，**不能是另一套内容**
- 要**口语化**：去掉 Markdown 标记、代码块、表格、列表符号、文件路径
- **长度是硬约束**：中文合成实测约 5 字/秒，**超过 150 字就明显拖沓**（150 字已是 30 秒）。
  → **整篇朗读是禁止的**。用 `tts_report` 让它压缩，不要自己把全文塞给 `tts_speak`
- 用户看完文字会立刻听到语音，**两者不一致会让人困惑**

> 正确：文字里写"已修复 3 个问题、2 个测试失败"，语音念"修复了三个问题，还有两个测试没过"
> 错误：文字是详细报告，语音把整篇念一遍 —— 35 秒起步，用户会直接关掉

### 3. 按人设改写

用第 1 步读到的性格，把播报稿改写成该角色的口气。人设里写了禁忌（比如不许卖萌、不许用某类比喻）就严格遵守。

### 4. 调用插件

**汇报一律用 `tts_report`，不要用 `tts_speak`。**

```
tts_report({ text: "<完整汇报原文，Markdown 也行>", voice: "<声线包名>" })
```

`tts_report` 会先压缩再朗读，并**返回它实际念出来的文本**（`report.spokenText`），你可以据此确认没有漏掉关键信息。

**为什么必须用它**：中文语音实测约 5 字/秒。一份 500 字的汇报整篇念完要 100 秒 —— 比读它还慢，用户会关掉声音。压缩到 120 字约 24 秒。

**只有短句才用 `tts_speak`**：一句话确认、一条结论、一句提醒。

**压缩策略**：

| 策略 | 何时用 |
|---|---|
| `local`（默认） | 本地句子排序。**零额外模型调用、零额外等待** —— 绝大多数情况用这个 |
| `subagent` | 起步 agent 重写。**只在用户明确要求，或本地压缩明显丢失关键结论时用** —— 多一次模型调用，明显更慢 |

`budget` 默认取插件配置的 `reportBudget`（约 120 字 / 9 秒）。正式汇报可放宽到 150-180，简短提醒压到 80。

- `saveTo`：**不要传**，除非用户明确要音频文件
- 返回值里的 `report.strategy` 告诉你走的是哪条路；如果是 `local` 且结果丢了你认为重要的内容，可以调大 `budget` 重念一次，**不要**擅自改走 subagent

### 5. 回报失败，不要掩饰

`tts_speak` 返回失败时，**照实说明**（例如声线包缺失、引擎未安装、设备静音），并给出下一步。不要静默跳过 —— 用户以为在播、实际没声音，比报错更糟。

## 调整人设

用户要求改性格/语气/声线时：

1. 编辑 `soul/<角色>.md` 里对应的小节（语气、节奏、禁忌）
2. 换声线改 `soul/voice-pack.json` 的 `pack` 字段
3. **改完立刻用新的人设念一句**验证，不要只改不试

细节与写法示例见 [docs/persona-guide.md](docs/persona-guide.md)。

## 边界

- **人设只影响播报稿的措辞**，不影响你实际的工作质量、判断和事实准确性。**绝不能为了人设而含糊或夸大结论。**
- 失败、风险、坏消息**优先用平实语气说清楚**，人设是次要的。
- 不播报任何敏感内容（凭据、密钥、个人隐私文本）—— 语音会被旁人听到，而屏幕不会。
